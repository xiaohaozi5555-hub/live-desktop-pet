# 直播桌宠

面向恐怖游戏主播的 Windows 桌面互动角色：实时接收游戏、露脸、语音与弹幕事件，并以动作、语音和气泡作出低延迟回应。

## 它解决什么问题

直播桌宠如果只会循环动画，很快会从“角色”退化成屏幕装饰。本项目让角色能理解直播中的多种信号，并在不打断主播节奏的前提下及时回应。工程重点不是堆叠模型能力，而是把感知、决策、表现和控制拆成可独立验证的模块，同时用状态机约束角色何时回应、何时保持安静。离线样例库让没有直播设备和平台权限时也能回放关键链路。

## 架构

```text
游戏画面 / 露脸 / 弹幕 / 语音
              │ perception.*
              ▼
┌──────────┐  packages/contract  ┌──────────┐
│  感知层   │ ─────────────────▶ │  决策层   │
└──────────┘    统一事件契约       └────┬─────┘
      ▲                                │ action.*
      │ command.*                      ▼
┌─────┴────┐                      ┌──────────┐
│  控制层   │                      │  表现层   │
└──────────┘                      └──────────┘
 面板/语音/弹幕白名单               Electron 角色窗/TTS/气泡

离线验证：fixtures → mock bus → brain → action
真实运行：Python/Electron → 本地 TCP JSON Lines 总线
```

所有模块只依赖 `packages/contract/` 的事件定义，不依赖其他模块的内部实现。详细设计见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 关键设计决策

1. 四层经一份事件契约解耦，模块只依赖契约、不依赖实现，以便各模块独立开发、验证和替换。
2. 响应采用双路分流：低延迟、高确定性场景走本地规则而不调用模型，复杂理解才进入多模态路径，以控制延迟与调用成本；没有把全部事件统一交给大模型。
3. 人设一致性作为约束项统一管理语气、拒答与行为边界，而非仅作文案润色。
4. 声纹验证限定语音指令权限，弹幕指令另设主播与房管白名单；没有把所有输入都视为可信控制信号。
5. 状态机包含冷却、合批与防刷屏，显式控制“什么时候必须闭嘴”，而不是让每个事件都触发回复。
6. 样例库支持无设备环境下的离线回放验证，放弃只靠实播手工验收的方式。
7. 文档采用“状态覆盖写、决策追加写”；能力状态表明确标注可用、待接入与已弃用，避免多份进度说明互相冲突。

## 已知限制

- 实时弹幕仍需要平台官方玩法的 APP ID 与互动数据权限；仓库内夹具只证明归一化、决策和离线链路。
- 透明窗口在部分直播采集方式下可能定格，当前提供绿幕与软件渲染兼容路径，但仍需按具体直播环境验证。
- 持续监听麦克风的运行时接线仍待完成；声纹、ASR 与指令链路已有独立验证。
- 当前主要面向 Windows 与抖音直播伴侣，未验证其他桌面系统和直播平台。

## 技术栈

- Python 3.11、asyncio、本地 TCP JSON Lines
- Electron、Node.js
- NumPy、MSS、DeepFace、MediaPipe、Resemblyzer
- edge-tts 与可选多模态模型接口

## 目录结构

```text
apps/                 角色窗口与控制面板
services/             感知、决策、对话和本地总线服务
packages/contract/    跨进程事件 schema 与校验器
fixtures/             已脱敏的离线回放样例
scripts/              集成验证、回放和 Windows 启动脚本
assets/               角色资源
docs/                 平台合规说明
```

## 本地运行

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Set-Location apps\character
npm install
Set-Location ..\..
start-pet.cmd
```

需要模型或平台凭据的模块，请先复制 `.env.example` 为 `.env` 并在本机填写；不要提交 `.env`。完整依赖与验证命令见 [DEVELOPMENT.md](DEVELOPMENT.md) 和 [RUNNING.md](RUNNING.md)。
