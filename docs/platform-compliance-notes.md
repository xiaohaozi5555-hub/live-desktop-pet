# 抖音直播玩法 提审/审核规则要点（对本桌宠项目的影响）

> 来源：抖音开放平台官方文档（测试与提审 / 资质规范 / 运营规范）+ 个人开发者实践。
> 注：最细的《运营规范》条款正文为登录/JS 渲染，未全抓到；以官方最新页面与《服务协议》为准。

## 一、对我们有利（可行性 + 契合点）

- **个人开发者可做**：个人主体申请软著、符合规范即可上架；有主播用你的玩法就有直播间礼物分成。
- **形态天然契合**：官方专门有"互动工具（仅直播伴侣）"类目，我们的桌宠正是这类。
- **官方给 mock 自测工具**（礼物/评论/点赞/粉丝团数据），与我们已建的离线夹具思路一致。
- **露脸+有声要求我们天然满足**（你本就是露脸主播）。
- **纯自研素材规避授权风险**：我们角色是纯代码手绘 SVG + edge-tts，未用任何他人 IP/音乐/肖像/表情包 → 不触发第三方著作权/肖像授权要求。

## 二、硬性要求（提审必须满足）

1. **软件著作权（软著）——强制前置**。
   - 需"非游戏/APP 类"软著；软著名称与玩法名称**基本一致**；软著主体与开放平台入驻主体**完全一致**（个人=你本人），不支持转授权；同一软著仅对应一款玩法。
   - → 你需先拿这套桌宠代码去**登记一个软著**（名称与玩法名对齐，如"直播互动桌宠"）。
2. 开发者账户完成注册 + 资质认证；配置开播测试账号（≤3 个测试成员）。
3. **提审材料**：游戏包体 + 版本号 + 【上线内容说明文档】(权限须设为"获得链接的人可阅读") + 简要与详细版本描述(详细≤10 行) + 提审自查 checklist。
4. **礼物与指令数量上限**：配置**最多 10 个**评论指令词；并给每个礼物/指令的效果说明。

   ⚠️ **礼物数量的"≤8 款"是过时说法，2026-07-26 查证订正**：原先这里写"从平台弹幕礼物池选最多 8 款礼物"，那是照着**直播玩法**文档记的，而且指的是"你能往自己玩法的礼物面板里配置几款专属道具做特效"，**不是"能收到哪些礼物的送礼数据"**——两件事。我们走的是**互动工具**路线（见第六节），官方《互动工具开发者指南》更新日志 2024.06.28 明确写着"从伴侣 8.0.0 版本开始，送礼数据的礼物种类**从 8 款提升至 40+ 款**"，同版本新增了「获取礼物列表」API，即名单是运行时查询的动态列表。**具体 40+ 款是哪些、包不包括小心心/跑车/热气球这类常规打赏礼物，文档没有列出**，需要调该 API 或在开放平台后台礼物菜单里看。填提案礼物表前先去后台确认，不要再照搬"8 款"这个数字。
5. **内测调试规则**：开播测试需露脸、始终有声、不许挂机/黑屏；用户送礼真实付费且不可退；mock 自测数据**不得推送到线上服务器**。

## 三、红线/限制（功能设计要避开）

- 平台保留广泛解释权，违规分级处罚。通用红线：诱导/欺骗送礼、未成年人保护、低俗涉黄涉赌、外链导流、虚假宣传。
- **⚠️ 对我们最敏感：「帮主播求礼物/催打赏」**。"诱导送礼"是重点监管方向。我们的"求礼物模式"话术必须收敛为**感谢/答谢/活跃气氛**基调，避免露骨索取（如"快刷礼物给我""快打赏"）——否则提审或上线易判违规。
- 未成年人：桌宠形象是 6–12 岁女孩，注意别把内容/话术做得像面向未成年人或诱导未成年人消费。

## 四、提案建议（怎么写更易过审）

- 玩法定位：**"直播伴侣里的桌面互动助手/弹幕互动桌宠"**——强调进场欢迎、礼物答谢、弹幕互动、活跃气氛、提升观众参与感（评审看"玩法与直播适配度 / 商业化空间 / 美术品质"）。
- 把"求礼物"改写为**"礼物答谢与感谢互动"**，规避诱导送礼红线。
- 礼物：映射到桌宠分级答谢动作，具体挂哪些礼物**以开放平台后台实际礼物列表为准**（"≤8 款"已订正，见上方第四条）；评论指令词 ≤10 个，对应我们的关键词控制。
- 软著名 / 玩法名 / 应用名尽量对齐一致。

## 六、登录控制台实测补充（2026-07-14）

- **流程比想的更细**：不是"注册应用拿AppID+申请互动数据能力"这么简单，是官方四步 创建直播玩法 → **提案评估** → 开发玩法&提审 → 玩法发布。AppID 已有（`宠物助手`，`tt037b75c69d1eea8210`），卡在"提案评估"——这一步要交 demo 视频+题材/系统设计文案，模板是飞书文档（创建副本填写），2个工作日左右出结果。点赞/礼物/评论等真实数据能力，全部要提案通过之后才能申请，绕不开。
- **玩法题材硬性红线**：明确禁止"血腥、暴力、惊悚"内容——对我们这种"恐怖游戏直播桌宠"定位需要格外注意提案里的**措辞**：桌宠本身可爱、不涉及血腥暴力，但提案文案不能自己往"恐怖/惊悚"上定位，要写成"直播互动陪伴助手"这类去恐怖化描述。
- **官方禁用词清单**（气泡/话术不能出现）：游戏、玩家、背包、血条、赛季、BUFF、DEBUFF、人头、QTE、AOE、平A、KDA、CD、PVP、PVE、RPG、MOBA、AVG、DPS、T、HP、排位、连杀、吃鸡、抽奖、盲盒、礼盒。
- **随机性设计规则**：不允许抽奖/盲盒式包装；礼物触发的随机效果最多一款礼物能带，且只能有外观差异、不能有数值/数量差异。
- **弹幕原文投屏**：未经平台书面同意，不能把弹幕评论原文直接展示到玩法画面里。
- **品类选择**：官方主流"直播玩法"是阵营对战型（选手/阵营互相PK），我们这种单人陪伴反应属于"创新品类"，提案里要讲清楚为什么这也算"有互动内容/有指令效果/实时合理反馈"。
- **必接能力**：点赞、礼物、评论三项是"必接"（强制），粉丝团可选——现在项目只做了礼物+评论，点赞这块完全没有对应的桌宠反应设计，需要补。
- **技术对接细节**（真实提审时才用得上）：玩法客户端就是普通 exe（Electron 官方文档里就有专门给 Electron 包体的已知问题修复：GPU崩溃要加 `no-sandbox` 启动参数），直播伴侣启动时传 `-token=xxx`，玩法服务端要用这个 token 换 room_id；打包格式是 `xx_1.0.0.zip`（纯英文名+版本号，解压后是根目录）。直播伴侣采集这类透明窗口推荐用"游戏进程"素材源+勾选"允许窗口透明"，比通用"窗口捕获"更贴合官方设计。
- **自用不用等公开上线**：把自己直播账号加进"开播测试账号"名单（最多3个），可以豁免"玩法挂载门槛"，用"调试版本"直接在真实直播里用，不需要走完公开上线那条重流程。
