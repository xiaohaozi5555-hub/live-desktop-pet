# 角色立绘生成任务书

给负责实际出图的工具/人（当前：Codex）看的规格说明。背景：本机能调用的图像生成渠道都不通
（DashScope key 没开通通义万相；本机几个"生图 skill"是空壳无实际脚本），所以生成这一步换别的
工具/key 来做，我（Claude）负责把前端代码和验收标准准备好，出图后我来审核接线。

`gen_character.py` 里已经写了同样这套 BASE_DESC/STYLES/STATES + DashScope 调用实现，如果
Codex 那边能配出一把有权限的图像 key，直接改 `.env` 的 `PET_IMAGE_*` 跑这个脚本最省事
（`python assets/character/gen_character.py candidates` / `all --style=xxx`）。如果用别的生图
方式，就按下面的文件名 + 描述产出，效果一致即可。

## 硬性技术要求

1. **背景必须是真透明 PNG（alpha 通道），不能是纯色背景块。** 桌宠窗口本身透明置顶叠加在直播
   画面上，带底色的插画会变成一块难看的方块。文生图模型通常画不出真透明——让模型画纯白色背景，
   再用抠图/背景移除转成透明 PNG（`gen_character.py` 里的 `_remove_background` 用 floodfill 实现
   了一版简单可用的，背景干净的纯白色图效果不错，可以直接调用或照着实现）。
2. **12 张图必须是同一个角色**（同样发型/发色、瞳色、服装配色、体型），只有姿势/表情不同。这是
   最容易翻车的点——独立的文生图调用容易长相漂移。建议：能用图生图/参考图/固定 seed 就用；或者
   先出一张定稿的 idle 再拿它当参考生成其余状态。出完我会肉眼比对一致性，不一致的会打回重出。
3. **构图**：全身正面/全身立绘，人物居中，四周留白，建议统一竖版画布（如 3:4 或 2:3），所有状态
   同一构图/相机距离，切换时不会忽大忽小。
4. 负向约束：不要文字、水印、签名、logo、边框、多人、拼图分格、裁切不全、模糊、变形、多余肢体、
   手指错误、低质量、写实真人、性暗示/暴露、背景渐变、背景纹理、背景杂色。

## 第三步（决定要做）：部分状态升级成逐帧动画

用户明确反馈"单纯的整图晃动/震动达不到预期"，要真的动起来（手脚/表情实际变化），不再只是
CSS 让整张图晃。渲染器（`apps/character/renderer.js`）已经改好支持这个，规则如下：

- **文件名约定**：某状态如果有多帧，第 1 帧还是原来的 `<state>.png`（不用重新生成），第 2 帧起
  按顺序追加 `<state>_2.png`、`<state>_3.png`……比如 `wave.png`、`wave_2.png`、`wave_3.png`…
- **不需要一次性把 12 个状态全部做成动画**——先挑几个视觉上最值得投入的状态试（建议从
  `wave`、`scared`、`thank_big` 开始：手势清楚、有明确的起止动作，比较容易出连续帧还不崩人设），
  效果好、角色一致性稳，再逐步扩展到其它状态；剩下的状态留着第二步的单张静态图当兜底，不会拖垮
  整体进度，也是这次唯一的容错空间——单帧和多帧状态可以混着来，程序自动识别，不需要都一样多帧。
- **每个状态几帧**：建议 4-6 帧，不用严格数量，抓得住动作弧线（比如挥手：手放下→抬起→挥→放下）
  比凑够帧数更重要。
- **播放方式**：渲染器按「1→2→…→N→…→2→1」来回摆动播放（ping-pong），不是从最后一帧跳回第一帧
  循环——这意味着**不需要让最后一帧和第一帧能无缝衔接**，只要相邻帧之间过渡自然、能顺着原路"倒
  放"回去看起来合理就行（挥手/晃动/鞠躬这类本来就是来回摆动的动作，这个约束反而更省事）。
- **一致性要求同上，且更严格**：同一个状态内相邻帧之间除了要产生的那个动作变化外，其它都不能变
  （发型、服装、背景、构图、光影都要稳），不然播放起来会闪烁/跳动感很重，比单张图之间不一致更
  容易穿帮。做不到稳定就该状态先只交 1 帧（静态），不要硬凑多帧。

## 交付之后（Claude 审核清单）

- 核对文件名是否精确匹配（含多帧状态的 `_2`/`_3` 后缀）
- 目测背景是否真的透明（拖到深色背景下检查有没有白边/色块）
- 目测所有帧角色是否一致（发型发色、服装、体型、构图）
- 跑 `apps/character/verify_character.js`，并在浏览器里实际打开 `apps/character/index.html` 切一遍全部状态，看动效/切图效果，多帧状态额外看播放是否顺滑、有没有闪烁
- 有问题会指出具体哪张图/哪个状态、哪里不对，打回重出
